## Findings

1. **High — human style gate bypassed in UI.** `style.js` displayed “Learned” on the automated
   `learned` flag alone. Task 020b replaces it with “Experimental profile · human review pending”.
   No human approval has been recorded or inferred.
2. **High — evaluation is not unseen-work proof.** `style/eval.rs::split_pairs` partitions
   generated pairs, not assets/projects. `trainer.rs::build_pairs` cross-products the same
   positive/negative pools, so train and eval reuse media (and repeated evidence may duplicate
   pairs). `evaluate` measures the residual margin, while production ranks general + scaled
   residual + query/context terms. The synthetic success is not evidence that the deployed
   ranking improves on new user work. Remediation and human approval are still open.
3. **High — stale personal evidence can survive withdrawal.** The trainer intentionally retains
   the previous active profile below the sample floor, including after confirmed examples are
   disabled. The current test confirms that behavior. Reset is an explicit immediate fallback;
   reliable evidence withdrawal needs invalidation/retraining semantics before a learning claim.
4. **Medium — plan feedback needed a real context key.** `record_feedback` previously saved only
   `query`, but the trainer reads `context`. Task 020b adds an optional `contextKey` bridge
   argument, preserving legacy calls while scoping the plan's explicit picks. Plan edits,
   reordering, removals, and version restores do not infer feedback.
5. **Medium — candidate provenance was incomplete for the UI.** Candidates did not export the
   effective profile ID/version/context. Task 020b exports that from the ranking request and
   freezes it on selection. A brief without a profile is General provenance, not Personalized.
6. **Medium — the referenced Task 020 implementation plan was not committed.** Neither main nor
   PR #33 contains `.tasks/done/TASK-020-impl-plan.md`. The replacement file explicitly labels
   itself a reconstruction from the shipped API and current user requirements.
7. **Remaining scope — full sequence intelligence is not implemented.** 020a offers aesthetic
   ranking and brief-based search; its penalty breakdown is usability, not sequence repetition.
   The plan stores editable pacing/treatment intent. 020b must not label those as automatic
   sequence optimization or rendered treatment. Task 020 acceptance remains partial on this point.
8. **Test gap — Mac-only timeout test was invalid and unexecuted in CI.** Full local workspace
   tests failed because a 30-second sleep was expected to hit the production 120-second timeout.
   The helper now accepts a test deadline (1 second), retaining the production 120-second ceiling.
   macOS CI now runs pipeline unit tests as well as native app tests/Clippy and blocking UI tests.
